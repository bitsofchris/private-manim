## As recorded

A good LLM wiki needs four layers. A place where agents can write for agents, a clean surface for humans to read, a curated layer of slowly changing context and rules that you review, and a janitor that keeps it all up to date and consistent.

The agent layer is written by agents for other agents. Agents can be as verbose as they need to be. This can include details that they need to resume a task later, like hashes, branches, commits. You never need to read it or go here.

The human layer is the clean, distilled view that you link out, and that goes to these detailed agent notes when necessary. Think of a dashboard or a Kanban board. It's less about reviewing what the agent's up to and more about managing your own context.

The curated layer, this is the slowly changing context that you need to handle with care. These are the skills and rules, the conventions of your repo.

And then you need the janitor. This looks to catch conflicting rules in your agent notes before they spread. And it cleans up old material so the human layer stays useful.

With all four layers, you can build a strong agentic knowledge base for research, personal growth, project work, or anything else.
