# Plan: a design system and a self-improving process for Shorts

**Name:** design-system
**Description:** Turn the house style, the shared library and the runbook
into something agents can follow without a human catching layout mistakes
on contact sheets, and that gets better after every video.
**When to use:** the status page for this work. Move to `docs/archive/`
when the loop has run for three videos.
**How it works:** rules become code where they can (tokens, layout check,
tests), prose keeps the why, and every video ends with a retro that feeds
the next one. Evidence in `docs/research/2026-10-03-shorts-craft.md`.

## Phases

### Phase 1: rules become code (highest leverage)

1. `BocShortScene.check_layout(allow_band=False)`: every `Text` ≥ label
   floor (code text ≥ code floor), every text and hero inside `safe`,
   no two text bounding boxes overlap, nothing in the band unless allowed.
   Called at the end of `construct` by every Short beat; raises with the
   offending mobjects named. `tools/lint_short.py` builds the scene with
   `-s` (last frame only) to run it fast. Tests on synthetic layouts.
2. Caption hold check in `assemble.py`: any caption shorter than
   `len(text)/15` seconds is flagged; `captions_from_transcript.py` merges
   chunks to satisfy it.
3. Tokens: `EASE_ENTER / EASE_EXIT / EASE_STANDARD`, `OP_HERO / OP_CONTEXT /
   OP_SCAFFOLD`, `CAPTION_CPS`; `tokens.yaml` generated by a tiny script
   and checked in tests to match `style.py`.
4. Frame-0 title: `BocShortScene.title_card(question)` places the
   question (5–8 words) in the band at frame 0; `assemble.py` starts word
   captions after it. Runbook step 1 requires the question text.

### Phase 2: the library

5. Promote on second use, with the 004–008 one-offs as the first batch:
   `prob_bars`, `card`/`chip`, `token_stream`, `net_glyph`, `ghostify`,
   `restroke`, `code_card`, `neuron`, `tiny_net`, `loss_bowl`,
   `comp_graph`, `token_matrix`. Each: a module under `_shared/parts/`,
   a test, a reference frame from `gallery.py`.
6. Pair transitions where they recur (card → box, box → stack, bars →
   bars refill) as functions that return the animation, so the identity
   rule is encoded, not remembered.
7. `graveyard/` for `_old_*.py` and anything retired.

### Phase 3: the loop

8. Runbook step 11, retro: at hand-off the agent writes
   `docs/retros/NNN.md` from a template: Chris's change requests verbatim,
   the rule or part that was missing, where it went (rule / token / part /
   tool / test), and a candidates update. `CHANGELOG.md` gets a line per
   system change.
9. Storyboard step gains the motion-role tag per beat (connect, co-vary,
   process, symbol sense, generalize) and the hook rule (frame 0 = the
   finished visual moving + the question on screen; question spoken in
   the first second; last line a takeaway, no outro).
10. `ARCHITECTURE.md` and a trimmed `CLAUDE.md` that points at it.

## Order of work

Phase 1 items 1 and 4 first (they would have caught every 008 fix and
they change what agents see on frame 0), then 5 for the 008 and 007 parts,
then 8 so the next video runs the loop, then the rest.

## Not doing

- `manim-voiceover` for timing: our VO-first pipeline already gives exact
  beat windows; per-word bookmarks would replace hand cues, worth a spike
  later, not now.
- A YAML-first design system: `style.py` stays the source, YAML is a
  generated mirror.
